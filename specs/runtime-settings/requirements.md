# Runtime Settings Requirements

## Goal

让单一管理员无需 SSH 即可调整产品雷达的 AI、自动发现、市场和成本参数，同时不暴露服务器机密，也不改变“筛选值得开发产品”的核心判断链路。

## User stories

1. 作为管理员，我希望在网站内切换 AI Provider、模型、超时和归并批量，以便适配不同中转能力。
2. 作为管理员，我希望调整自动发现时段、市场与成本上限，以便控制更新节奏和真实费用。
3. 作为管理员，我希望替换并测试 AI Key，但系统绝不能回显已经保存的 Key。
4. 作为管理员，我希望失败任务显示可理解的中文原因，并能在修正设置后重新执行。

## Acceptance criteria

- 当管理员打开设置页时，系统应展示当前生效的非敏感配置和各数据源连接状态。
- 当管理员保存合法设置时，系统应持久化配置，并从下一次新任务开始使用；正在执行的任务不应被中途改变。
- 当管理员把 AI 超时设置为 600 秒时，系统应只把它用于 AI 请求；DataForSEO HTTP 与异步任务超时应保持独立。
- 当自动发现存在超过单批上限的待处理信号时，系统应按批归并，并在同一任务内继续处理后续批次，直到达到批次数上限或没有新信号。
- 当管理员替换 AI Key 时，系统应加密保存、只返回“已配置”状态，并且不得通过读取接口返回明文。
- 当管理员测试 AI 连接时，系统应使用待保存或当前有效配置发起一次不重试的最小调用，并返回中文成功或失败结果。
- 当 AI SDK 返回空消息或 `<none>` 时，任务记录应显示可操作的中文错误，而不是原始占位文本。
- 当管理员修改服务器端口、数据库路径、登录密码或 Session Secret 等基础设施配置时，系统不应通过网页提供此能力。

## Non-goals

- 不在网页中管理服务器用户、端口、数据库文件、备份目录或登录凭据。
- 不回显或导出任何 API Key。
- 不为设置系统引入独立外部数据库或配置中心。
