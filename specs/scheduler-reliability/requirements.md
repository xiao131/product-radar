# 定时任务可靠性

## 目标

在不增加重复付费调用的前提下，保证自动发现、调研和备份不会被失败的手动或命令行任务错误拦截，并让调度结果可见。

## 验收标准

1. 当当天任意来源的同类任务已成功完成时，系统应跳过该次定时任务并记录原因。
2. 当当天只有失败的手动或命令行任务时，系统应仍执行一次定时任务。
3. 当当天已经尝试过同类定时任务时，系统不应再次自动执行，避免重复费用。
4. 当任务被成功任务满足而跳过时，运行记录应显示“已跳过”和中文原因。
5. 运行状态页应显示调度器最近检查时间、下一次检查时间，以及备份、发现、调研的下一次计划时间。
6. 服务重启后，系统应继续根据数据库中的当天记录作出相同判断。

## 非目标

- 不引入外部队列、系统 cron 或新的数据库服务。
- 不自动重试当天已经失败的定时付费任务。
