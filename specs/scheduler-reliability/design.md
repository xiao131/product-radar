# 设计

- 将“当天成功”和“当天定时尝试”拆成两个判断：成功任务可来自任意触发方式；定时尝试只统计 `scheduled` 且不包含 `SKIPPED`。
- 定时任务决策顺序：已有成功结果 -> 记录一次跳过；已有定时尝试 -> 静默等待次日；否则执行任务。
- 跳过记录沿用 `job_runs`，状态为 `SKIPPED`，不创建新表。
- 调度器心跳保存在当前进程内，由运行状态 API 暴露；任务历史和是否已运行仍以 SQLite 为准。
- 下一次计划时间由当前北京时间、配置小时和当天任务状态计算。
- 前端沿用现有运行状态页面，只增加一块紧凑的调度信息和 `SKIPPED` 状态样式。
- 各类任务使用独立异常边界；失败会记录任务类型和原因，但不会中断后续任务。

## 测试

- 单元测试覆盖手动失败、手动成功、定时失败、跳过记录去重，以及前序任务失败后继续执行。
- API 测试覆盖调度状态字段。
- 浏览器验证运行状态页的中文展示和响应式布局。
